How FFmpeg Works

A deep dive into the world's leading multimedia framework engine.

The Core Workflow

FFmpeg operates on a simple but powerful pipeline. It reads raw containers, extracts packets, decodes them into raw frames, processes them (like adding the subtitles you styled!), re-encodes them, and muxes them back into a container.

[Input File] -> (Demuxer) -> [Encoded Packets] -> (Decoder)
-> [Raw Frames] -> (Filters/Processing) -> [Raw Frames]
-> (Encoder) -> [Encoded Packets] -> (Muxer) -> [Output File]

The Libav Libraries (The API)

FFmpeg is not just a command-line tool; it is a collection of powerful libraries that you can use in C, C++, Python, or Node.js:

libavcodec

The heart of FFmpeg. Contains all the encoders and decoders for audio and video.

libavformat

Handles "muxing" and "demuxing" (reading and writing container formats like MP4, MKV, AVI).

libavfilter

This is where the magic happens for subtitles, resizing, and color correction.

libswscale

Performs highly optimized image scaling and colorspace/pixel format conversion operations.

FFmpeg Filtering (force_style)

When you use the tool on the previous page, you are interacting with libavfilter. The force_style parameter overrides the ASS (Advanced Substation Alpha) properties inside the filter chain. FFmpeg parses these strings and applies them to the video frames in real-time during the transcoding process.
